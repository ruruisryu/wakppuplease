# 실제 검증 기록

2026-10-01 · 로컬 구현·GitHub Pages 배포·공개 플레이 검증 완료.

## 실행한 검사

- `npm test`: 경제·중복 완료·재고 상한·실제 운반·자동 가공·구매·벽/시설 충돌·손상 저장 검증 **8개 통과**.
- `npm run build`: TypeScript 검사와 Vite 프로덕션 빌드 성공. 잠금 파일 포함.
- Playwright CLI + Chromium headless로 키보드 이동 → 작업대 진입 → 실제 포인터 파쇄 → 매장 복귀 → 집기 → 운반 → 선반 보충 → 고객 결제를 연결해서 확인.
- 자연 성장 세션에서 재화·해금·진행 주입 없이 18개 직접 생산/판매. 트레이 강화 82.4초, 운반 직원 고용 262.2초, 첫 확장과 직원 자동 판매 확인 504.6초. 그때 19개 생산·19개 판매, 두 번째 직원이 만든 상품 1개 포함. 이 수치는 반복 입력 봇과 당시 헤드리스 환경의 관찰이며 사람의 평균 플레이 시간이나 재미 검수 결과가 아니다.
- 후속 수정: ESC 기본 dialog 취소와 키 입력의 충돌 해결, 그림자 1024로 조절, 낮은 프레임에서도 경제 시간이 과도하게 느려지지 않도록 최대 25ms 하위 스텝, 가려진 선반 전달 원을 앞으로 옮김, 가공 직원의 사용하지 않는 운반 메시 숨김. 수정 후 파쇄·운반·판매와 관련 규칙 테스트를 재확인했다. 전체 8분 성장 시간은 수정 전 측정값이다.
- 최종 파쇄 입력 검사: 17.0초에 완료, `made=1`, `tray=1`, `coins=0`. 이후 실제 운반·고객 판매로 `sold=1`, `coins=10`. 입력 봇의 느린 고정 패턴을 포함하므로 목표 작업 길이 6~12초를 달성했다고 주장하지 않는다.
- 저장: 실제로 번 코인과 carry/runner/expansion 해금이 새로고침 후 일치. 보류 파쇄 진행과 음소거 설정 복원 확인. 초기화 확인 화면과 새 게임, 손상 저장의 알림·복구 확인.
- PC: 시설·벽에 직접 이동하여 충돌, ESC 일시정지/재개, 모달 뒤 이동 차단 확인. 일시정지 중 고객 시계·위치 변화 없음.
- 모바일 에뮬레이션: 390×844, 844×390. CDP touchStart/Move/End/Cancel을 사용하여 실제 터치 스틱 이동, 작업 진입, 파쇄 드래그, 취소 후 손상 중단, 모달 뒤 터치 차단, 음소거 저장 복원 확인. 화면 크기와 문서 크기 일치, 스크롤 없음. 물리 휴대폰 검증은 아니다.
- 프로덕션 `127.0.0.1:4173` 및 Pages 형태의 `127.0.0.1:4174/WAKPPU_Please/`에서 검증. HTML/JS/CSS/한국어 폰트 모두 200, 새로고침 성공. 정상 플레이에서 JS 오류·실패 요청 없음.

## 성능과 미검증

Headless Chromium, 1280×900, 확장 후 매장: 고품질 1초 표본 22/22/21fps, 가벼운 설정 23/23/24fps. 파쇄 단독 후속 표본 31fps. Chromium ReadPixels GPU stall 경고가 관찰됐다. **60fps 달성 미확인**이며 실제 GPU 브라우저·휴대폰·Safari·Firefox는 검증하지 않았다. 기능 자동 검증은 완료했지만 재미, 피로도, 손맛, 실제 스피커 청감은 사용자 검수가 필요하다.

껍질은 80개 패치로 나뉜 근사 파쇄, 파편 간 충돌 없음. 고객/직원끼리 충돌하지 않아 서로 겹쳐 지나갈 수 있다. 상품 1종, 매장 1개, 확장 1단계, 직원 2종의 작은 MVP다. 클라우드 저장·오프라인 생산 없음.
